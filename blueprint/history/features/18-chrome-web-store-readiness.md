# Feature: Chrome Web Store Readiness

**From build-plan:** feature 18
**Build attempt:** 1
**Branch:** feature/chrome-web-store-readiness
**Status:** verified

## Goal

Footly can be packaged and submitted to the Chrome Web Store. That means:

- a real icon at every size Chrome uses;
- version `1.0.0`;
- a zip built from the production build;
- written store listing material: descriptions, single-purpose statement,
  permission justifications, data disclosures, the privacy policy link, and a
  screenshot guide.

Nothing is uploaded or published; that stays the user's action.

## In scope

- **Icon (decision 1b, drawn, for the user's approval in review):**
  - **Design:** a rounded square in Footly's accent green (`#15803d`) with a
    bold white "F", and a small white ball dot to the lower right. It is simple
    enough to read at 16px.
  - **Generated by a dependency-free Node script** (`scripts/generate-icons.mjs`,
    using built-in `zlib` for PNG encoding and supersampling for smooth edges)
    into `public/icons/icon-16.png`, `icon-32.png`, `icon-48.png`, and
    `icon-128.png`.
  - **Wiring:** the manifest declares `icons` (16, 32, 48, 128) and
    `action.default_icon` (16, 32). Notifications use `icon-128.png`.
  - **Cleanup:** the old placeholder `notification-128.png` and the unused Vite
    `public/favicon.svg` (which still ships in `dist/`) are removed.
- **Version (decision 2a):** `1.0.0` in `package.json` and `package-lock.json`.
  The manifest already reads it from `package.json`.
- **Package script:** `npm run package` runs the build, then zips the contents of
  `dist/` (with `manifest.json` at the zip root) to
  `release/footly-<version>.zip` using the system `zip` command. `release/` is
  ignored by Git.
- **Store listing (`STORE_LISTING.md`):**
  - name, a short description of 132 characters or fewer, and a detailed
    description built only from shipped features;
  - the single-purpose statement;
  - a justification for each permission, taken word for word from
    `src/lib/privacy.ts`;
  - data usage answers (collects no user data, no remote code);
  - the privacy policy URL (decision 3a):
    `https://github.com/saidMounaim/footly-extension/blob/main/PRIVACY.md`;
  - a screenshot guide: 1280×800, which screens to capture and in which theme;
  - a submission checklist.

  The store category is listed as "to choose at submission"; that is not decided
  here.
- **README:** replace the Vite template text with a short Footly README covering
  what it is, development, build, package, the privacy link, and the store
  listing file.
- **MV3 compliance guard:** extend `manifest.config.test.ts` to assert:
  - the icons and default icon at the exact paths;
  - version `1.0.0`;
  - no `host_permissions`, `content_scripts`, or `content_security_policy`
    override.

## Out of scope

- Uploading, publishing, or any Chrome Web Store dashboard action.
- Taking the screenshots or creating promotional tiles (the guide is provided;
  capturing needs the user's Chrome).
- Hosting the privacy policy anywhere other than the GitHub file.
- Store category, pricing, and region choices.

## Build loop

Continuous run: implement all steps, verify each, then complete locally.
`workflow.checkpointCommits` is `disabled`.

## Build steps

- [x] **1. Icon.**
  - Add `scripts/generate-icons.mjs`. It draws at 8× and averages down, using
    only Node built-ins.
  - Generate the four PNGs into `public/icons/`.
  - Update the manifest (`icons`, `action.default_icon`) and `ICON_PATH` in
    `src/background.ts`.
  - Remove `notification-128.png` and `public/favicon.svg`.
  - Extend the manifest test.

  **Done when:**
  - `npm test` and `npm run build` pass;
  - `sips` reports each PNG at its exact size;
  - `dist/` contains the four icons and no `favicon.svg`;
  - the 128px icon is shown in the review packet for approval.

- [x] **2. Version and package script.**
  - Set version `1.0.0` in `package.json` and the lockfile root.
  - Add the `package` script, and ignore `release/`.

  **Done when:**
  - `npm run package` produces `release/footly-1.0.0.zip`;
  - `unzip -l` shows `manifest.json` at the root;
  - the built `dist/manifest.json` has version `1.0.0` and the icons;
  - the manifest test passes.

- [x] **3. Store listing and README.**
  - Write `STORE_LISTING.md` and replace `README.md`.

  **Done when:**
  - the short description is 132 characters or fewer (counted by a command);
  - every permission justification matches `src/lib/privacy.ts` word for word;
  - the privacy URL is the decided one;
  - lint and build still pass.

## Testing

- Vitest covers the manifest contract (icons, version, no host access, no content
  scripts, no CSP override). The icon script is checked by its output sizes, and
  the zip by `unzip -l`.
- The icon's look needs the user's approval. Screenshots are left to the user,
  using the guide.

## Notes for the AI

- The `zip` command must run inside `dist/` (`cd dist && zip -r ...`), so
  `manifest.json` sits at the archive root.
- The listing text describes only shipped behavior. Do not promise Botola Pro;
  ESPN doesn't serve it.
- Keep `PRIVACY.md` unchanged; the listing links to it.
